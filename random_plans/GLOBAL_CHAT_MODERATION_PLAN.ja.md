# グローバルチャットのモデレーション計画

## 目標

メッセージを他のサーバーへ中継する前に、本文と画像添付ファイルをモデレーションします。
明確な脅威には低コストで説明可能なチェックを使い、判断が難しいものは単一の機械学習モデルに頼らず、モデレーターによる確認に回します。

## 現在の動作

現在のグローバルチャットのリスナーは、メッセージの送信頻度を制限し、本文の不適切な言葉やDiscord招待リンクをチェックします。`censor_urls()` は一部のURLをプレースホルダーに置き換え、設定済みの許可リストとブロックリストにあるドメインを照合しますが、ブロック対象のURLが含まれていても、現状ではメッセージの中継を止めません。また、URL抽出はスキーム付きのURLを対象に設定されています。画像や動画の添付ファイルは、モデレーションによる確認なしで中継される場合があります。

モデレーションチェックは、`src/poxbot/platforms/discord/extensions/global_chat.py` のブロードキャスト処理が各サーバーへの送信を始める前に実行します。

## 提案するメッセージ処理パイプライン

1. **既存のチェックを適用する。** 現在のスパム対策と不適切な言葉の検出を維持します。
2. **本文を正規化する。** 照合前にUnicodeを正規化し、一般的なゼロ幅文字や書式制御文字を除去または統一します。表示には元の本文を使い、解析には正規化した本文だけを使用します。
3. **メッセージ本文とURLを調べる。**
   - スキーム付きURLと一般的なスキームなしURLの両方を抽出し、ホスト名、サブドメイン、国際化ドメイン名を正規化します。
   - Discord招待リンクの形式と、既知の悪意あるドメイン／URLを確認します。
   - 明示的な詐欺フレーズやパターンを照合し、必要に応じて、モデレーターが確認した少数の詐欺メッセージとの類似性を調べます。
   - URLレピュテーションの照会は、キャッシュとタイムアウトを設けた外部シグナルとして扱います。ユーザーが送信した任意のURLをBotホストから直接取得しないでください。
4. **添付ファイルを安全に調べる。**
   - 対象をサポートする画像形式に限定し、ファイルサイズと画像寸法に上限を設けます。
   - SHA-256ハッシュを比較し、同一ファイルを検出します。
   - 知られている詐欺画像のサイズ変更、再圧縮、軽微な編集を検出するため、知覚ハッシュ（pHash/dHash）を比較します。
   - 画像にOCRを実行して、表示されているテキストやURLを抽出します。抽出したテキストは、本文と同じ正規化、フレーズ照合、URLチェックに通します。
   - 知覚ハッシュとOCRで重要な亜種を見逃す場合に限り、画像埋め込み表現の利用を検討します。埋め込みは、一般的な類似度しきい値ではなく、管理された既知の詐欺例の集合と比較します。
5. **メッセージごとに証拠をまとめる。** 理由コードと信頼度／証拠を含む、`allow`、`block`、`review` のようなモデレーション結果を生成します。まず明確で決定的なルールを適用します。曖昧なテキスト類似度や画像類似度だけを根拠にユーザーをBANしないでください。
6. **ブロードキャストを制御する。** モデレーション結果が許可の場合に限り、中継します。確認済みの脅威はブロックまたは保留し、判断が難しいものは、利用可能であればモデレーター確認キューへ送ります。
7. **必要最小限のモデレーション情報を記録する。** メッセージ本文、完全なURL、OCR結果、添付ファイルのデータは、既定ではログに記録せず、結果と理由のみを集計します。人による確認に証拠が必要な場合は、アクセスを制御した確認手段を用意します。

## 推奨する実装フェーズ

### フェーズ1: 決定的な本文・リンクチェック

- スキームなしURLも含めてURLを抽出・正規化します。
- 確認済みのブロックリスト該当を、表示URLの置き換えだけで済ませず、中継停止につなげます。
- Discord招待リンクの変種と、よくある詐欺文言のパターンを追加し、テストします。
- 許可リストの動作を明確にし、高信頼度の脅威判定を誤って上書きしないようにします。
- Unicodeによる難読化、句読点、大文字・小文字、スキームなしURL、サブドメイン、許可リスト／ブロックリストの各ケースをテストします。

### フェーズ2: 軽量な画像重複検出

- サポート対象の画像を、厳格なサイズ・寸法上限のもとで検証・デコードします。
- モデレーターが確認した詐欺画像のSHA-256ハッシュと知覚ハッシュを保存します。
- 新しい添付ファイルを保存済みの集合と比較し、知覚ハッシュのハミング距離を測定します。
- 既知の詐欺例と通常のグローバルチャット画像を使って、しきい値を調整します。
- 完全一致、サイズ変更／再圧縮、軽微な編集、無関係な画像、破損または過大なファイルをテストします。

### フェーズ3: OCRと共通のテキスト解析

- Discordのイベントループをブロックしないよう、同時実行数を制限したワーカーまたは非同期ジョブでOCRを実行します。
- 画像からテキストとURLを抽出し、メッセージ本文と同じチェックに通します。
- OCRエンジンを選ぶ前に、デプロイ先のホストで起動時間、画像ごとの処理時間、常駐メモリ、動作を計測します。
- OCR失敗をログ／メトリクス上で明示し、解析できない場合にメッセージを許可するか保留するかを定義します。

### フェーズ4: 任意の意味解析モデル

- テストで重要な見逃しが確認された場合、詐欺メッセージ類似度のためのテキスト埋め込み／分類器と、詐欺画像の亜種検出のための画像埋め込みを評価します。
- タスクに適したモデルで、ライセンスとモデルカードが明確なものだけを使用します。
- 感情分析を詐欺分類の代わりに使わないでください。
- 詐欺に特化した学習と評価を行わずに、一般的なImageNetのMobileNetV2クラスを詐欺検出器として使用しないでください。
- MobileCLIPのような小型候補を、代表性のあるラベル付きデータセットでベースラインと比較します。CLIP系の類似度が示すのは見た目の類似性であり、悪意そのものではありません。
- 適合率と誤検出率が許容範囲になるまでは、モデルの予測は補助情報として扱います。

## モデルと依存関係に関する注意

- SHA-256と知覚ハッシュは低コストなので、画像類似度チェックの最初の手段にします。
- Pillowは画像のデコードやサイズ変更に使えますが、悪意あるコンテンツを分類するものではありません。
- EasyOCRはテキストを抽出できますが、PyTorchを使用し、モデルの重みをメモリに読み込みます。パッケージ名やモデルファイルのサイズだけで判断せず、実行時全体のコストを測定してください。
- NSFW検出器が判定するのは性的コンテンツのカテゴリであり、詐欺ではありません。
- `lxyuan/distilbert-base-multilingual-cased-sentiments-student` が予測するのは感情クラスであり、詐欺／フィッシングのリスクではありません。
- 一般的なMobileNetV2の事前学習済みチェックポイントはImageNetの物体クラス向けであり、詐欺検出向けではありません。
- 標準的なCLIP ViT-B/32は比較的負荷が高く、モデルカードでも未検証のデプロイに警告しています。より小さな画像・テキストモデルを後で評価する場合も、タスクに即した検証が必要です。

## 脅威インジケーターのカタログ

既知の悪意あるインジケーターは、バージョン管理されたJSONファイル
（例: `src/poxbot/assets/global_chat_threats.json`）に保存し、
`src/poxbot/features/moderation/` の `GlobalChatModerator` で読み込んで検証します。JSONはこのPythonプロジェクトに自然に適合し、起動時の検証も容易です。既存の設定ツールやメンテナーの都合に合う場合はXMLも使用できますが、両方を並行管理せず、どちらか一方を正式な形式にしてください。

各レコードには次の情報を含めます。

- 安定したレコードIDとインジケーター種別（`sha256`、`phash`、`url_domain`、`text_pattern`など）。
- 該当する場合はハッシュアルゴリズムと値。完全一致ハッシュと知覚ハッシュは別々に保存します。知覚ハッシュは近似照合であり、暗号学的な証明として扱ってはいけません。
- 悪意があると判断した理由のカテゴリと短い説明。
- 未確認の報告を確認済みの一致として扱わないための信頼度、情報源／由来、確認状態。
- 登録日時、確認日時、任意の有効期限。
- 必要に応じて、モデレーターのみが参照する安全な証拠参照先。元画像、メッセージ本文全体、個人情報はカタログに保存しないでください。

例:

```json
{
  "schema_version": 1,
  "indicators": [
    {
      "id": "scam-image-0001",
      "type": "image_hash",
      "algorithm": "phash",
      "value": "9f172786e71f1e00",
      "max_distance": 4,
      "reason": {
        "category": "giveaway_scam",
        "description": "配信者になりすました偽の賞品企画画像として確認済み"
      },
      "confidence": 0.98,
      "status": "confirmed",
      "source": "moderator_report",
      "created_at": "2026-10-09T00:00:00Z",
      "reviewed_at": "2026-10-09T00:00:00Z",
      "expires_at": null,
      "metadata": {
        "evidence_ref": "moderation-case-0001",
        "notes": "調整済みのハミング距離しきい値で比較し、近似一致は確認に回す"
      }
    }
  ]
}
```

スキーマを検証し、不正なレコードは黙って無視せず拒否します。編集権限は信頼できるメンテナー／モデレーターに限定し、`status`を`confirmed`にする前に報告内容を確認します。古くなったインジケーターは定期的に期限切れにするか、再確認してください。`confidence`の値だけで処罰を決定せず、インジケーター種別、照合距離、モデレーションポリシーと組み合わせます。

初期実装では、確認済みのSHA-256完全一致、URLドメイン、テキストフレーズの一致は中継をブロックします。pHashの一致と未確認インジケーターは確認のため保留します。サイズ超過、アニメーション、未対応形式、デコード不能な画像も中継せず保留します。解析対象は静止画のJPEG、PNG、WebPで、画像ごとの上限は8 MiB、メッセージ内の画像合計上限は16 MiB、添付ファイル読み込みの合計タイムアウトは10秒です。初期カタログは空で、確認済みインジケーターをJSONファイルに追加して運用します。

## 運用上の安全対策

- SSRFや悪意あるリダイレクトのリスクを避けるため、Botプロセスからユーザー提供URLをダウンロードしたり開いたりしないでください。
- 画像サイズ、タイムアウト、同時実行数に上限を設け、重複コンテンツはキャッシュします。
- ユーザーに通知し、データの取り扱いが許容される場合を除き、プライベートなメッセージや画像を第三者APIに送信しないでください。
- 第三者レピュテーションフィードは任意機能とし、レート制限、障害、データの鮮度、利用規約を考慮します。
- 未検証の類似度だけを根拠にユーザーへ自動的な処罰を行わないでください。モデレーターによる確認と、誤検出を訂正する手段を用意します。
- ブロックリスト／ハッシュ集合の更新を信頼できるモデレーターに限定し、登録内容を定期的に見直します。

## 評価基準

強制適用を有効にする前に、確認済みの詐欺テキスト／画像、無害なグローバルチャットの内容、編集・再圧縮された詐欺画像、多言語の例、難読化されたURLを含むラベル付きテストセットを作成します。以下を測定します。

- 各検出器と統合判定の適合率・再現率。
- 無害な内容に対する誤検出率。
- 起動時および実際のメッセージ量を想定したCPU・メモリ使用量。
- メッセージごとの処理時間の中央値と高パーセンタイル値。
- OCR、ローカルモデル、レピュテーションサービスが利用できない場合の障害時動作。

可能であれば、まずログ記録のみ、またはモデレーター確認のみのモードで始め、誤検出を確認してから、高信頼度で決定的な一致に限ってブロックを有効にします。
